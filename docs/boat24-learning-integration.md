# 公開予想から次回モデルへの接続：今回の改修範囲

対象は予想保存・結果ラベル・検証条件・学習ケース・モデル採用の接続。不足項目33件全体、直前配信の高速化、映像解析、収益性の実証までを完了扱いしない。

## 完了条件と確認

| 条件 | 実装と確認 |
| --- | --- |
| 公開固定した版を選ぶ | 公開receiptと固定planのhashを照合。プロトコル開始日以降は公開証拠のない別保存版へ学習対象を差し替えない。公開証拠がない過去日の研究標本は区別して保持。 |
| 正解ラベルを接続 | 公式結果から確認できた1〜6着を保存。落水・妨害等に順位を作らない。6艇着順が不足する場合は、同一R・上位着順一致のCSVを照合し、不成立は理由を記録。 |
| 結果訂正を反映 | 下位着順・本番情報の追記も結果の版へ含め、予想入力は不変のまま訂正結果から別case IDを生成。 |
| 収支条件を一致 | 締切前に保存・公開固定した共通対照の可変点数・100円単位配分で比較。12点均等の研究比較は残すが、候補採用の根拠には使わない。 |
| 件数だけで採用しない | 最低400R・14日・候補購入100Rに加え、誤差改善、黒字、回収率100％超、基準以上の回収率・利益、選択買い目の校正、実現ガミなしを確認。これらの閾値は利益保証ではない。損失連続数と最大ドローダウンも記録。 |
| 実際に学習したケースを追跡 | 対象に選べた件数と実際の学習使用件数を区別。入力・正解ラベル・旧モデル・公開commit・case IDを記録し、新モデルの学習根拠digestを新しい予想へ添付。 |
| 旧モデルを反映済みと呼ばない | 旧モデルは日中固定のまま。新条件の再学習前は画面に再学習待ちを表示。旧研究条件の採用判定をそのまま新条件の承認として扱わない。 |

## 検証証拠

- Python 231件の回帰テスト通過。公開版選択、公開証拠欠落、訂正、順位欠落、結果後の比較案変更、将来入力、不十分な標本による採用拒否を含む。
- 公式の下関4R結果fixtureには「落」「妨」がある。確認できた4着までを保持し、5・6着を捏造しない。正常6着順のfixture変形でも解析確認。
- 実際の学習ループに、日次CSVがない状態から公開固定カードと公式6艇着順が届くことをテスト。入力中の前走成績も保持。
- 本番固定記録17Rを新しい経路へ通し、17Rの比較を構築。全て見送り、購入0Rで採用不可。旧入力は変更されていない。
- 当該17Rの旧公式保存には下位着順が不足し、CSVなしで6艇学習ラベルが揃うのは1R。残りを学習済みと偽らない。新しい解析と一致するCSV照合で順次補う。

## 本番で残る確認

1. 新しい集計policyと除外理由が公開画面へ反映されること。
2. 次の予定再学習が成功し、新モデルに実際の公開固定case lineageが入ること。
3. そのモデルIDと学習根拠digestが次の事前公開予想に入ること。
4. 新条件の購入候補を前向きに積み上げ、利益改善の有無を評価すること。

再学習と利益改善を、このコード公開だけで完了と報告しない。予想・検証・学習は同じサイト内で扱い、別サービスに分割しない。
